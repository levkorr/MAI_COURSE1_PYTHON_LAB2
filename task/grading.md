## Обязательные проверки

- Пустой файл создаёт нулевой отчёт без падения.
- Один файл CSV и эквивалентный JSONL дают одинаковую статистику.
- Несколько файлов агрегируются без потери событий.
- Кириллица сохраняется в сообщениях и отчёте.
- Неверный JSON в строке 7 сообщает строку 7.
- Неверная дата сообщает поле и строку.
- Без `--skip-invalid` обработка прекращается.
- С `--skip-invalid` остальные строки учитываются.
- Top-5 сортируется детерминированно при равных значениях.
- Исходные файлы не изменяются.
- Большой вход не читается целиком.

## Проверка потоковости

Полный балл за потоковость ставится при выполнении всех условий:

- parser возвращает iterator/generator или обрабатывает запись по одной;
- отсутствует `readlines()` и полный `list(file)`;
- агрегация не хранит все события;
- студент объясняет объём дополнительной памяти.

Если все события накапливаются в списке, за критерий ставится не более 5 из 15.

## Начисление за тесты — 15

- 4: parser CSV/JSONL;
- 3: граничные и повреждённые строки;
- 3: несколько файлов и агрегация;
- 3: CLI и временный каталог;
- 2: тесты независимы и детерминированы.

## Защита

1. Добавить уровень `NOTICE` либо объяснить, где должна находиться его валидация.
2. Изменить top-5 на top-N без копирования логики.
3. Показать место, гарантирующее построчную обработку.

## Ограничители

- Используется полное чтение файла — максимум 84.
- Повреждённая строка молча игнорируется — максимум 74.
- Исходный файл изменяется — максимум 49.
- Нет integration test файла — тестирование не выше 9 из 15.
